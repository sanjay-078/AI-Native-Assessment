# AI use and review

I used Codex to inspect the supplied assessment contract and kit, write the Python API/worker, tests and documentation, and run the local commands. I used Ollama's local `qwen2.5:3b` through its OpenAI-compatible endpoint for the actual-model evaluation. The kit model was used only for deterministic systems checks. No hosted model key was needed.

One important error in the generated worker code was the PostgreSQL claim query's clause order: it placed `FOR UPDATE SKIP LOCKED` before `LIMIT 1`. I corrected it to `LIMIT 1 FOR UPDATE SKIP LOCKED` before testing, then verified claims, concurrent duplicate submissions and the worker restart through the real containers. The first test command also used the `pytest` executable, which failed to import the application package; I changed it to `python -m pytest` and reran the suite.

I rejected the model's first raw outputs as trustworthy policy text. Qwen sometimes merged nonadjacent sentences into a false quote, omitted citation fields, proposed an action for a paid payment, or returned empty prose for unsupported questions. The application checks the document identity against tenant-scoped active policy, supplies the exact source quote, and enforces action eligibility from the read tool. It traces validation failures and permits one malformed-output repair. The evaluation report retains the first unsuccessful development run rather than hiding it.

I checked the core with production-function tests, the supplied smoke checker, fault injection, a worker restart, and development/public audit evaluations through the API. In the completion pass I used the installed Taste Skill to redesign the desktop UI, inspected the rendered screen, then checked a live request, citation display, run reload, and the approval request flow in a browser. I reran 12 application tests and the 14-check fixture smoke test, restoring the two Ollama workers afterward. The results and limitations are recorded in `EVAL.md`.

In the final repair pass, I inspected the two failed insurance-fee traces and the persisted model message before editing. The model had selected human review but returned a null answer, and the validator accepted a retrieved fee document as enough context to reach repair. I added a general material-term evidence check and a safe human-review normalization, then tested unsupported paraphrases and supported fee questions through the real model. I also replaced blocking 429 sleeps with a durable due time and persisted a selected payment read before deferral. I checked a simulated 25-second retry against PostgreSQL with two claim attempts, reran all 20 application tests, the 14-check fixture smoke test, and fresh real-model development and public audit sets. The original audit and failed runs remain visible; `EVAL.md` labels each rerun.
