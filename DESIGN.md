# Scaling note

One million requests a day averages 11.6 requests/second. Assume a 5× business-hour peak: about 58 requests/second. If half are payment requests (two model calls) and half are policy requests (one), the peak is about 87 model calls/second. At five seconds per call, that needs roughly 435 concurrent model slots. The local Qwen setup cannot serve that traffic; even the two-worker demonstration was only a bounded assessment load.

At 600 input and 180 output tokens per model call, 1.5 million daily calls would use about 900 million input and 270 million output tokens. At **illustrative** prices of $1 per million input tokens and $3 per million output tokens, that is $1,710/day. These are scenario rates, not a measured cost or vendor quote. Local Ollama has no per-token API invoice; hardware and power are excluded. Fixture tokens are synthetic.

The first bottleneck is model throughput. The default single worker handles one run or action at a time; two workers ran concurrently in the recorded load checks, but increased queue wait under the local model. PostgreSQL then absorbs claim, checkpoint, and trace writes. At ten writes per run, one million daily requests imply about 116 writes/second on average and 580/second at peak, before actions and retries. Admission currently caps queued plus running work at 16 per tenant and returns 429 with `Retry-After`; there is no global capacity budget across tenants. A provider outage can fill those queues, causing rejections until capacity returns.

I would next add a global admission budget tied to measured provider capacity, then scale model serving and workers together. I would watch p95 acknowledgement and completion latency separately, oldest queued age, lease recoveries, model concurrency/latency/429s, read-tool failures, invalid-output and citation-correction rates, action reconciliation count, and PostgreSQL CPU, lock waits, and storage growth. If database claiming becomes the bottleneck, I would batch claims or add a broker for delivery while PostgreSQL remains the source of truth. External writes keep the stable idempotency key.
